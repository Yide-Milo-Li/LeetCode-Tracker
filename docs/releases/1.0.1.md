# Release 1.0.1 — Windows startup fix

This patch fixes the local-service startup failure in the Windows 1.0.0 installer. Download `LeetCode-Tracker_1.0.1_x64-setup.exe` and `SHA256SUMS.txt` from [Release 1.0.1](https://github.com/Yide-Milo-Li/LeetCode-Tracker/releases/tag/v1.0.1).

## Fixed

Tauri returns canonical Windows resource paths with a verbatim prefix. The private Node runtime could fail while resolving that script entrypoint and exit before sending readiness. The host now safely simplifies equivalent Win32 paths without changing resource selection or searching PATH.

A native integration regression uses the actual bundled backend and private Node runtime under a canonical installation path containing Chinese characters and spaces. It checks the handshake, authenticated health, and graceful shutdown through Windows Job ownership.

## Upgrade and data

Close the running app, then install 1.0.1. Keep the existing application data directory. Do not delete your SQLite database, WAL, or lock files to work around the old startup error. This patch changes process startup and application version metadata; it introduces no database schema migration. The original 1.0.0 tag and assets remain unchanged, with a warning in their release description.

## Verification and limits

The startup regression failed before the fix and passed afterward. Local verification includes seven Rust tests, 312 JavaScript/Web/sidecar tests, TypeScript and documentation checks, Rust fmt/clippy, and Windows installer packaging. The installed 1.0.1 host was checked for ready status, authenticated health 200 with version 1.0.1, graceful close, and restart with one sidecar. An in-place installation succeeded on Windows 11. No SQLite profile existed before that installation; after first launch, repeating the installation preserved the database file hashes. This does not establish preservation of a populated 1.0.0 profile.

The installer is unsigned and requires WebView2. A missing WebView2 runtime requires the configured bootstrapper download. These targeted local checks do not establish clean-VM coverage, Windows 10 compatibility, a full upgrade/downgrade matrix, complete WebView2 UI/native-dialog acceptance, or performance targets. Full SQLite migration/custom data-directory selection, signing, and automatic updates remain unfinished. Provider availability was not tested; API keys remain in local SQLite without OS credential encryption.
